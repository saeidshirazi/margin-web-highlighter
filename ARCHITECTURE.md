# Architecture

Margin is a Manifest V3 extension built from readable ES modules with esbuild. There is no application server. Node.js is needed only for development and release packaging.

Version 0.5 adds `drive-client.js` (Chrome Identity OAuth, app-data-only Drive API, bounded validated downloads and resumable uploads), `sync-state.js` (canonical URL identities, per-record causal clocks, tombstones, merge/projection and conflict copies), `drive-sync.js` (background orchestration/retry/account binding) and `drive-ui.js` (consent/status/setup/control UI). Research remains local; sync is opt-in. Each device writes a separate converged replica file. The existing settings store holds an internal full-state offline journal atomically with synced data; ordinary snapshots/backups read only the main settings record. Google identity/account state stays outside research payloads. See `GOOGLE-DRIVE.md` for protocol, setup, limits and validation scope.

Network work runs outside the background mutation queue. Sync checkpoints before downloading, rechecks local changes under that queue, then atomically applies data and journal. Audio saves/deletes and backup imports use background messages. Large PDFs and backups stage data in IndexedDB and pass only a transfer ID through the queue, avoiding Chrome's message-size limit. The database schema and backup format stay at version 2. Existing local page IDs are preserved; wire records use canonical URLs for page references.

Version 0.4 introduces `audio.js` for native recording lifecycle and `audio-notes.js` for persistent audio assets/players. The IndexedDB v2 upgrade creates a `pageId` index on the existing assets store without clearing existing stores. PDF assets retain their original page-key scheme; audio has independent IDs and page/highlight references. Backup format 2 accepts audio, while the importer still reads format 1. Imports retain audio source identities for repeat-safe merging. Page deletion cascades to audio. Local media is decoded from object URLs that are revoked on cleanup.

`capture.js` is a stable extension tab for append-only quick notes, audio capture/import, and returning to the source while recording. Notes append transactionally; successful text save is cleared before a possible audio-save retry to avoid duplication. Dialogs expose pre-submit stop/finalization and attachment-save events, so both newly created and existing notes receive the correct source ID. Sidebar drafts are held through highlight refreshes. Audio and dictation are deliberately separate, with microphone track release and permission-pending teardown tests.

`tests/native-flows.mjs` exercises actual MediaRecorder/getUserMedia and audio decoding against Chrome's generated test audio input, not a mocked recorder. It also verifies note/highlight coexistence and complete audio backup recovery. A separate opt-in live Google Translate probe uses synthetic text. Provider protocol fixtures remain necessary for repeatable speech-to-text and authenticated Google Cloud paths; they are labeled separately from native coverage.

Version 0.3 places the details pane inside the library workspace grid. Collapse restores a full-width library; split mode sizes the content and pane as separate columns. Width is clamped, stored in settings, and controllable with pointer or keyboard. Narrow layouts put the panel above the cards. Refresh preserves pane state, scroll, and resize-handle focus.

`speech.js` manages one recognition session per editor. Interim text remains outside saved notes; final results insert at the cursor and are deduplicated by result index. `note-tools.js` enhances note editors. The dialog's pre-submit event waits for recognition stop/finalization before collecting FormData. Close/cancel aborts sessions, and disposed availability checks cannot start a microphone later.

`translation.js` provides validated local and official Google Cloud v2 adapters. Source detection and local model sessions are explicitly disposed. `translation-ui.js` handles output language/defaults, consent, host permission, cancellation, stale-result suppression, RTL output, and appending results to notes. The Google key lives only in trusted extension session storage and is absent from database snapshots. Raw provider error payloads are not surfaced, avoiding accidental secret disclosure. Providers are never silently switched to the cloud. HTTP requests use omitted credentials, a 30-second timeout, and a key header. `languages.js` shares code validation and display/direction helpers.

Version 0.2 adds `transfer.js` for destination-independent Markdown and bundle serialization, `markdown-import.js` for content-hashed local document import, `brand.js` for the shared vector mark, and `polish.css` for the refined responsive interface. ZIP compression is bundled locally with fflate. `scripts/brand.mjs` generates the distributable logo kit. Markdown previews and import rendering remain sanitized. Clipboard export explicitly writes both `text/html` and `text/plain` after a user action; no Notion API or credentials are involved.

## Boundaries

- `background.js` is the message router and service-worker write coordinator. Content-script requests are limited to the sender's current canonical URL and page's own highlights. Library-only operations are rejected from content scripts.
- `db.js` owns IndexedDB schema version 1. Stores: pages (unique URL index), highlights (page index), cards (page index), settings, and assets (PDF bytes as base64 for portable backups). Related deletion and import writes are atomic transactions. Normal UI mutations are serialized through the service worker. File/PDF import and backup snapshots use direct extension-origin transactions to avoid Chrome runtime message-size limits.
- `anchor.js` indexes eligible text nodes and captures TextQuote-style exact/prefix/suffix selectors plus character offsets. Restoration tries positions, scores matching quotes by context and distance, then handles whitespace differences. Missing quotes are preserved in the database. Hash routes beginning with `/` or `!` retain separate identities; ordinary document anchors and common tracking parameters do not.
- `annotator.js` supplies reusable selection/edit controls in a closed shadow root. Native CSS Highlights render without wrapping or mutating the source article's text DOM, support overlaps, and keep independent styles per document region. Refresh generations prevent disposed or stale async loads from repainting.
- `content.js` hosts page annotation, Readability extraction, visible transcript capture, video seeking, and navigation detection. It does not use the page's JavaScript globals or download caption files.
- `library.js`, `panel.js`, and `popup.js` provide the research UI, Chrome sidebar, and action popup. Imported/user text is escaped; Markdown and article HTML pass through DOMPurify. Saved article HTML uses a restrictive allowlist.
- `reader.js` uses stored article/transcript content with no remote images/scripts. Video follow mode communicates with the already-open original site instead of embedding third-party players.
- `pdf.js` uses bundled PDF.js, worker, CMaps, fonts, and WASM. Canvas pages render when near the viewport; text-layer selections store page numbers and PDF coordinate quads. `pdf-lib` writes standard PDF Highlight annotations. PDF text for local AI is indexed from the first 500 pages.
- `backup.js` generates portable formats and optional AES-GCM encrypted backups. A backup snapshot reads every store in one consistent readonly transaction. Password derivation uses a random 16-byte salt, 310,000 PBKDF2-SHA-256 iterations, a 256-bit AES key, and a random 12-byte IV. There is no key persistence or recovery.
- `ai.js` feature-detects browser-local AI and uses at most 24,000 input characters. It never calls a remote inference endpoint. Model sessions are destroyed after each operation.

## Security and portability

All executable code and rendering dependencies are bundled in the extension. Manifest CSP disallows external scripts. Optional host permission supports requested PDF downloads (without credentials), explicit translation, and consented Drive sync. Drive uses OAuth bearer headers restricted to Google's API host. No remote favicon, font, cover-image, analytics, or error-reporting services are used. `chrome.storage.local` signals updates and stores Drive account/sync status; research data is never put into Chrome Sync.

Import validation happens before a write transaction. Imports remap IDs, preserve existing page metadata by canonical URL, merge distinct annotations, and preserve links between imported cards and highlights. Reimporting an unchanged backup does not duplicate its records. Backup preferences are included for portability/audit but do not overwrite the recipient's settings in this release.

Current scale tradeoffs: library search loads page/highlight metadata and article content in memory and scans records; a very large archive will need paginated indexes. Rendered PDF canvases remain mounted after first view, so very long documents can consume significant memory. PDF size and backup input limits are explicit, not claims of unlimited device capacity. These are documented extension points for later releases.

## Validation

`npm run check` runs ESLint, Node's tests with JSDOM/fake-indexeddb, and a release build. `npm run test:e2e` installs the built extension into a fresh Playwright Chromium profile, exercises real browser flows, parses exported PDF annotations, restores backups into an empty database, and records screenshots and JavaScript errors. The YouTube test uses controlled transcript markup and native video DOM behavior. Chrome's device-specific AI model is not mocked as a successful real model execution.

## Browser targets in 0.6

`src/platform.js` selects native Firefox promise APIs or Chromium APIs. `scripts/browser-manifest.mjs` generates Chrome/Edge service-worker manifests and Firefox event-background/sidebar/optional-data-consent declarations. `src/google-auth.js` keeps Chrome native authorization while Edge/Firefox use state-validated browser web OAuth, exact callbacks and session-only token caching. Stable public IDs are in `config/browser-ids.json`; local OAuth registration is excluded from source archives. Production builds contain no test interception. Drive tests inject a bootstrap only into a separate temporary fixture XPI. See CROSS-BROWSER.md for validation and remaining release gates.
